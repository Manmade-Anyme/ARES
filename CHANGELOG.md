# Changelog

All notable changes to the ARES trading system will be documented in this file.

## [Unreleased]

### Changed
- **MEDIUM-Confidence Breakouts Restored (TASK-184)**: `breakout_failure_min_score` lowered **3→2** (class default, so both profiles), reverting the TASK-172 bump. At 3 the engine fired only HIGH-confidence failed breakouts (score ≥60% of the matrix) and **silenced every MEDIUM one** (score 2/4 = 50%). ARES is used as a **manual-trading confirmation aid**, not only an autotrader — a MEDIUM breakout that agrees with an open position is useful confidence, one that disagrees is a prompt to reconsider, and a silent detector provides neither. The `AresSignal.confidence` field already labels MEDIUM vs HIGH so the trader weights it; the engine no longer pre-suppresses the MEDIUM tier. `closed_back` stays a hard gate and score 0-1 still never fires (noise floor intact). **This is an intentional product decision — do NOT re-raise to 3** (see the `breakout_failure_min_score` comment in `config_profiles.py`, `directives/TASK-184_restore-medium-breakout.md`, and `tests/unit/test_task184_medium_breakout.py`). Diagnosis: over 06-29→07-09 the three fader detectors went silent on 07-07→09; the audit traced breakout silence to this gate — 10 genuine closed-back candidates on 07-07 topped out at score 2 and were all filtered. Verified end-to-end: the real detector now fires 4 MEDIUM breakouts on 07-07 (min_score=3 baseline: 0). 250 tests green (4 new; the score-mechanic assertions in task174/task175/audit_p1 updated to check confidence/reason strings instead of fire-vs-None).

### Added
- **Kronos Live Probability Module (TASK-184)**: Decoupled observational consumer module (`ml_signal/kronos_consumer.py`) polling `ares_signals` for new signals, running multi-path Kronos-mini forecast inference on CPU, and posting follow-up barrier-hit probabilities ($P(\text{target before stop})$) to Discord without delaying core signal generation or trade execution. Includes vendored Kronos transformer model package and custom path decoder (`ml_signal/kronos_vendor/paths.py`). 265 unit tests green.
- **ML Offline Labeling & XGBoost Training Pipeline (TASK-183)**: The `ml_collection` feature log was growing ~350 rows/trading day but was **inert** — never labeled, never read by the trainer (`data.py` reads `trade_analytics`, not `ml_collection`), and XGBoost was dormant (empty `models/`, `ml_predictions=0`). New **offline, read-only** pipeline makes it trainable without touching any live-path file: `ml_signal/dataset.py` flattens the 7 feature-group JSON columns into a numeric matrix and self-labels every row by a **bidirectional forward-points triple-barrier** (from each candle: a clean ±`tp_points` move before the opposing `sl_points` stop within `lookforward` candles → 1, opposing stop first → 0, chop → dropped), **day-bounded** so a forward window never spans the overnight gap. `ml_signal/train_offline.py` (`python -m ml_signal.train_offline`) does a chronological (leak-free, small-data-safe) split, trains XGBoost, evaluates AUC/precision/feature-importance, and saves a model + a JSON report — inlining the fit/eval helpers (same `MLConfig` params) rather than importing `trainer.py`, which hard-imports the unneeded `optuna`. First live run: 2,688 rows → 168 labeled samples, AUC 0.547 (provisional — 2 weeks of mostly-flat data; rerun as trending data accumulates). **Zero changes to the live engine/collector/deployment.** 246 tests green (13 new). See ADR-183.

### Removed
- **Observation Gate + Speed/IV-Crush Filters Removed — Every Signal Trades (TASK-182)**: The observation-only mechanism is gone entirely — the `AresSignal.alert_only` field, exhaustion/continuation observation modes, the counter-trend trend-regime filter (`trend_filter_enabled`), the OBSERVATION-ONLY Discord formatting and the separate observation channel (`discord_observation_webhook_url`). Also removed the two remaining MEDIUM-suppressing engine filters: the flat-market **speed filter** (`speed_filter_window_candles`/`speed_filter_min_range_pts`) and the **anti-IV-crush filter** (`iv_crush_lookback_size`/`iv_crush_percentile`/`iv_crush_min_samples`, plus the per-side IV lookbacks). The **R:R gate is now the only protective filter** — every fired setup becomes a live trade unless its risk:reward is degenerate. Diagnosis: on trending days (07-06/07-07) these gates were neutering tradeable signals into observation-only alerts (07-06: 8/8 signals) or suppressing them, so the system "went quiet" despite the detectors firing normally. `continuation_enabled` is kept as a real off-switch; detector logic and scoring are unchanged. The speed filter's window/threshold (`speed_filter_window_candles` / `speed_filter_min_range_pts`) survive **only as a flat-market annotation** — a signal in a sub-threshold market still trades, but its alert gains a `Price is FLAT — market moving under 15 points` reason line at the bottom. 233 tests green.

### Changed
- **Observation Alert SL/Targets Restored (TASK-176)**: `alert_only` alerts keep the TASK-175 gray "👁️ OBSERVATION ONLY — NOT A TRADE" header but once again show the spot-level SL and T1/T2 targets (both the Discord embed and the text formatter) so observations can be evaluated against structure. The entry zone and the option sizing card (lots, option entry/SL/target) remain omitted — the alert still cannot be mistaken for a tradeable signal.
- **SL Buffers Removed (TASK-175)**: All 3 detectors now place the stop exactly at the structural reference — breakout level, OI wall strike, or exhaustion candle extreme. The `breakout_stop_buffer` / `oi_wall_stop_buffer` / `exhaustion_stop_buffer` config fields are deleted (today's #2056 would have stopped at 24350 instead of 24375). Tighter risk also means more setups pass the `min_rr_ratio` gate.
- **Observation-Only Alert Restyle (TASK-175)**: `alert_only` signals (counter-trend downgrades, exhaustion observation mode) now render with a gray "👁️ OBSERVATION ONLY — NOT A TRADE" title and carry no entry/SL/target/lot-sizing fields — signal #2056 was traded manually because the only marker was a reason line at the bottom. These signals are never tracked by the PositionManager, so no exit updates ever follow them.
- **Hardcoded Tunables Moved to Config (TASK-175)**: breakout deep-close depth (`breakout_deep_close_pts`), shared structural-target selection distances (`structural_target_min_distance_pts`, `target_1_fallback_min_pts`, `target_2_fallback_min_pts`), OI wall conviction multiplier + wick scoring gate (`oi_wall_conviction_multiplier`, `oi_wall_wick_min_range_pts` — the wick-score block also now honors `oi_wall_wick_rejection_ratio` instead of a duplicate hardcoded 0.4), exhaustion extreme-volume/doji factors, level proximity and volume-history size, position-manager dedupe tolerance (`trade_dedupe_tolerance_pts`), and the IV-crush minimum sample count (`iv_crush_min_samples`). The dead `breakout_resistance_proximity` field (defined but never read) was removed.
- **Breakout OI Scoring Fix (TASK-174)**: The failed-breakout score matrix shrinks from 5 to 4 conditions (weak volume, IV falling, writers active, deep close). `writers_holding` (OI >= previous, including zero change) is no longer scored — any growth past the active threshold implies holding, so scoring both awarded two points for a single OI reading; it survives as a reason string only. The `writers_active` OI-growth threshold moves from a hardcoded 3.0% into config (`breakout_writers_active_min_pct`: 10.0% non-expiry / 15.0% expiry) — intraminute ATM OI drift of 3-5% is common noise. `breakout_failure_min_score` stays 3 → a signal now needs 3 of 4 genuine confirmations. Motivated by the 06-Jul signal #2056 stop-out, where 2 of the 4 confidence points came from one noisy OI reading on a counter-trend trade.

### Added
- **Trend-Regime Filter (TASK-173)**: New engine filter derives an uptrend/downtrend regime from VWAP + PDH/PDL position (uptrend: close above both VWAP and PDL; downtrend: close below both VWAP and PDH). Counter-trend HIGH confidence signals are downgraded to observation-only (alert_only, same convention as exhaustion); counter-trend MEDIUM signals are suppressed outright. Tunable via `trend_filter_enabled` (audit item 16).
- **WebSocket Tick Feed for Exit Monitoring (TASK-173)**: New `fetchers/tick_feed.py` wraps dhanhq's `MarketFeed` WebSocket to stream live NIFTY spot LTP. The main loop now wakes every `tick_exit_check_interval_seconds` (default 2s) between the 60s REST poll cycles to run a tick-driven `PositionManager.update_trades` check, catching SL/T1/T2 hits sooner than the prior 60s-only cadence. Purely additive: best-effort connect with a REST-only fallback on failure, and the feed restarts alongside REST clients on credential reload (audit item 18).

### Added
- **Breakout Gate Tightened (TASK-172)**: `closed_back` no longer counts toward the failed-breakout score — it is the mandatory trigger, not a scored condition — and `breakout_failure_min_score` raised 2→3. A signal now needs 3 of 5 real confirmations (writers holding, weak volume, IV falling, writers active, deep close) instead of "closed back + one coin-flip" (audit items 7/8).
- **Anti-IV-Crush Filter v2 (TASK-172)**: HIGH-confidence signals are now exempt (the old filter killed every bullish entry regardless of quality); the check is symmetric — bullish entries check CE IV, bearish entries check PE IV via a new PE lookback; lookback lengthened 20→60 samples with both knobs in config (`iv_crush_lookback_size`, `iv_crush_percentile`). Observation-only signals pass through so exhaustion observation data keeps flowing (audit item 10).
- **Intrabar Exit Detection (TASK-172)**: `PositionManager.update_trades` checks SL/T1/T2 against the candle's high/low instead of only the 60s poll close (close-only detection cost an average +6.8 pts slippage per stop, worst +34.5). Exits are recorded fill-at-level (the touched stop/target price, for both wins and losses), and a candle spanning both the stop and a target resolves pessimistically as a stop-out (audit item 11).
- **Speed Filter in Config + Standardized Confidence Bars (TASK-172)**: the sluggish-market filter's window and threshold move into config profiles (`speed_filter_window_candles`, `speed_filter_min_range_pts`, previously hardcoded 15/15.0), and all detectors share one confidence rule via `models.confidence_from_score` — HIGH at ≥60% of the score matrix (breakout 3/5; OI wall and exhaustion 3/4, previously an inconsistent 2/4) (audit items 12/19).

### Fixed
- **signal_id Join (TASK-172)**: `Storage.log_signal` now captures the inserted `ares_signals.id` onto the signal, and `AnalyticsLogger.log_entry` writes it to `trade_analytics.signal_id` — previously NULL in every row, breaking the signals↔trades join (audit item 17).
- **Entry/Exit Timestamp Timezone Mismatch (TASK-172)**: entry timestamps were naive IST wall-clock stored as if UTC while exits logged real UTC, making hold-time analysis impossible. All entry-side timestamps are now labeled IST and converted to UTC on write via `storage.to_utc_iso` (audit item 18).
- **Duplicate add_trade Guard (TASK-172)**: a signal matching an already-open trade's setup, direction and entry (within 1 pt) is skipped — the 06-29 14:12 OI wall trade had been logged twice (audit finding 4).

### Added
- **Risk:Reward Gate (TASK-171)**: New engine filter rejects any signal whose risk (entry→SL) exceeds its reward (entry→T1), tunable via `min_rr_ratio` (1.0 in both profiles). Audit data showed OI-wall setups risking 40-46pts against a 35pt T1.
- **Time-Stop Risk-Off (TASK-171)**: An OPEN trade that hasn't reached T1 within `time_stop_minutes` (45 non-expiry / 30 expiry) gets its stop tightened to entry. The trade stays alive for T1/T2, but no-progress drift now exits at breakeven (`TIME_STOP` exit type) instead of full stop-loss.
- **Exhaustion Observation Mode (TASK-171)**: `exhaustion_alert_only=True` gates Exhaustion Reversal signals to alert+log only — no trade is created and the signal does not consume the engine cooldown. Live data: 7 of 8 closed exhaustion trades were full stop-outs (-211pts).
- **Cooldown Reset After Stop-Out (TASK-171)**: `update_trades` now returns exit events; a `SL_HIT` clears the engine signal cooldown so the next setup can be taken immediately instead of waiting out the 15-20min timer.
- **Backtest Validation**: Replaying the last 10 days of trades (ml_collection minute data, 40% T1-booking execution model): net P&L improves from -162.8pts to -36.7pts with the four gates active (13 of 22 trades gated).

### Fixed
- **Multi-Day Trade Carry (TASK-170)**: `PositionManager._initialize_db` previously deleted all previous-date rows from `active_trades` at startup, silently orphaning open trades (12 of 29 `trade_analytics` rows were stuck in `OPEN` with no exit ever logged). Trades are now loaded regardless of date and continue to be tracked across sessions until they hit T1/T2/SL, matching the intended data-collection behavior. Closed rows remain in the table untouched. Added a local-only backfill script (`scratch/restore_orphan_trades.py`, dry-run by default) to resurrect the 12 orphaned trades by recovering T1/T2/SL from matched `ares_signals` rows.

- **Exhaustion Detector Refactor**: Re-engineered the signal generation logic to prioritize structural levels over fixed offsets, falling back to fixed points only when structural levels are unavailable or too tight.

- **Discord Alert Formatting**: Refined the Discord embed structure to use textual emoji shortcodes (e.g., `:clock3:`, `:round_pushpin:`, `:white_check_mark:`, `:octagonal_sign:`, `:dart:`, `:zap:`, `:star:`, `:triangular_ruler:`, `:1234:`, and `:pencil:`) and bold text formatting for key trade metrics. ### Fixed
- **OI Wall Confirmation-Candle Requirement**: Fixed the `OIWallDetector` firing on a single shallow wall touch. It is now stateful (`update()` instead of `detect()`): a candle must show a genuine wick rejection (>=40% of range) to form a candidate, and the signal only fires if the following candle confirms by closing beyond the candidate candle's high/low. Unconfirmed candidates expire after one follow-up candle. Root-caused in [scratch/oi_wall_audit_20260702.md](file:///Users/manmadeanyme/Documents/Work/ARES/scratch/oi_wall_audit_20260702.md) after two weak/false signals (#2599, #0308) were traced to the single-candle, shallow-test decision rule in [OIWallDetector](file:///Users/manmadeanyme/Documents/Work/ARES/detectors/oi_wall.py).
- **Fly.io Persistence**: Resolved issues with Docker volume mounts that were interfering with source code visibility. Optimized the structure for persistent trade logging.
- **VWAP Reset Logic**: Fixed a bug where VWAP could persist across sessions; it now strictly resets at 09:15 IST daily.
- **Supabase RLS Permissions**: Resolved "42501: new row violates row-level security policy" errors by documenting and implementing the necessary SQL commands to disable or configure RLS for the `active_trades` and `ares_signals` tables.
- **Redundant Logging**: Removed excessive "warming up" console messages, replacing them with a single "BUFFERS FULL" confirmation once the system is active.
- **Position Manager Resilience**: Added lazy initialization and retry logic to `PositionManager` to ensure active trades are eventually loaded even if the initial Supabase connection fails due to temporary network outages.
