# TASK-010: Lot Size Integration and Delta-based Strike Selection

## Goal
Integrate  ot sizing calculations and custom delta-based strike selection into the ARES signaling engine. When a signal is generated, suggest the number of lots to trade based on available capital, option delta, and risk parameters. Save the calculations in Supabase and output them to both the console and Discord alerts.

---

## Acceptance Criteria

1. **Options Math Module (`options_math.py`)**:
   - Provide functions to calculate risk amount, point differences, premium translations, suggested lots, and affordable lots.
   - Implement delta-based contract selection to replace the default ATM strike logic:
     - Look for contracts with `abs(delta)` between `0.45` and `0.55` in the direction of the signal (CE for BULLISH, PE for BEARISH).
     - Select the contract with the lowest absolute delta (closest to `0.45`). If none match, fall back to the ATM contract.
     - Update the signal's `strike_to_trade` and `option_type` to this contract.

2. **Dhan Capital Fetching**:
   - Query Dhan API via `dhanhq` client using `get_fund_limits()`.
   - Parse the `'availabelBalance'` field from the response.
   - If the API fails or is down, fall back to a default capital of `₹100,000`.

3. **Risk & Sizing Parameters**:
   - Add new configurable properties to `TuningConfig` in `config_profiles.py`:
     - `risk_per_trade_pct: float = 10.0` (Default 10.0%)
     - `nifty_lot_size: int = 65` (Lot size for Nifty)
     - `default_capital: float = 100000.0` (Fallback capital)

4. **Independent execution**:
   - Ensure the new logic runs after the signal is generated by the engine but before any logging or notification logic is executed.
   - Do not alter the core detectors' underlying logic.

5. **Discord Notification**:
   - Format the Discord signal message to display a dedicated section "📐 FVG Lot Calculator" with the following metrics:
     - Option Entry Premium (LTP) and Delta
     - Calculated Suggested Lots (taking capital limits into account)
     - Option Stop Loss (LTP minus translated SL points)
     - Option Target 1 (LTP plus translated Target 1 points)

6. **Supabase Persistence**:
   - Save the lot calculations (suggested lots, option SL, option target, capital, delta, premium, risk percentage) inside the existing JSONB `reasons` list of the signal in `ares_signals` and inside the `market_context` dictionary in the `trade_analytics` table.

---

## Inputs
* Option chain from `OIFetcher` containing Greeks (specifically `delta`).
* Capital from Dhan API.
* Configuration properties for lot size, risk percentage, and default capital.

---

## Outputs
* Updated `AresSignal` object.
* Saved records in Supabase `ares_signals` and `trade_analytics` tables.
* Console output and Discord webhook messages populated with FVG lot sizing results.

---

## Edge Cases
* **No option matches delta range**: Fall back to the default ATM strike.
* **Dhan API Offline**: Log warning, send health alert if authentication fails, and fall back to `default_capital` (₹100,000) for sizing.
* **Zero or negative premium**: Fall back to 0 lots.
