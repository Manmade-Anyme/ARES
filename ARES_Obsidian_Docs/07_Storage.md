# Persistence Layer (Storage)

The Storage layer manages database interactions to persist signals and trade states using Supabase (PostgreSQL).

## Overview
- **Location:** `storage.py` and `position_manager.py`
- **Database:** Supabase (PostgreSQL)

## Tables

### 1. `ares_signals`
Records every signal generated by the system for post-session backtesting and auditing.
**Fields:**
- `id` (bigserial)
- `setup_type` (text)
- `direction` (text)
- `confidence` (text)
- `trigger_price`, `spot_at_signal`, `stop_loss`, `target_1`, `target_2` (numeric)
- `strike` (integer)
- `option_type` (text)
- `timestamp`, `created_at` (timestamptz)

### 2. `active_trades`
Maintained heavily by the [[06_Position_Manager]]. Stores the current state of live trades.
**Fields:**
- `id` (uuid)
- `setup_type`, `direction` (text)
- `entry_price`, `stop_loss`, `target_1`, `target_2` (numeric)
- `state` (text, default 'OPEN')
- `added_time_ist` (text)
- `created_at` (timestamptz)

## Security
If you are using the Anon/Public key, Row Level Security (RLS) policies must be disabled or properly configured for inserts and updates to succeed:
```sql
ALTER TABLE active_trades DISABLE ROW LEVEL SECURITY;
ALTER TABLE ares_signals DISABLE ROW LEVEL SECURITY;
```
