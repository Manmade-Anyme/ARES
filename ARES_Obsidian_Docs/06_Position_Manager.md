# Trade Management (Position Manager)

The `PositionManager` (located in `position_manager.py`) is responsible for tracking active trades generated by the system and trailing their stop losses based on live price action.

## Key Features

* **Trailing Stops:** Once a trade reaches Target 1 (T1), the Stop Loss is automatically trailed to the entry price to lock in a risk-free position.
* **State Management:** Trades can be in states like `OPEN`, `T1_HIT`, `CLOSED` (Stop Loss hit), or `STOPPED_OUT`.
* **Database Synchronization:** Valid trades are synced in real-time with the `active_trades` table in Supabase. On initialization, it loads today's active trades into memory to ensure no data loss across system restarts. It wipes old trades from previous days.
* **Discord Webhooks:** Whenever a trade state changes (e.g., hitting T1 or Stop Loss), it triggers an asynchronous Discord alert.

## Execution Flow

1. **`add_trade()`:** When the [[04_Engine]] outputs an `AresSignal`, `main.py` passes it to `PositionManager.add_trade()`. It formats the trade, sets the state to `OPEN`, stores it in memory, and pushes it asynchronously to Supabase.
2. **`update_trades()`:** Evaluated constantly against the live `spot_price`.
   * For **BULLISH** trades: If `spot_price >= target_1` and state is `OPEN`, state updates to `T1_HIT` and stop loss trails to `entry_price`. If `spot_price <= stop_loss`, state updates to `CLOSED`.
   * For **BEARISH** trades: Inverse logic.
   * If a state change occurs, it pushes the update to Supabase and fires a Discord alert.
